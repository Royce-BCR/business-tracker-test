Leads

The CRM database — one row per business, from cold contact to qualified opportunity. Click the chevron to open a lead's qualification detail. A lead can only be promoted into the Sales Pipeline once budget, decision-maker, timeline and competition are all filled — the gate that separates a lead from a real opportunity to quote. Promoting carries the record forward and switches its code from L- to S-.

Sales Pipeline

Live inquiry → quotable → quote sent → closed-won & signed. Click the chevron on any project to expand its stages — each stage carries its own dates and cost, and the project timeline & cost roll up from them. Use the Table / Board / Gantt switcher to see it as a stage board or a timeline. Only rows marked Real feed the forecast.

Project Pipeline

Delivery, from signed contract to sign-off and testimonial. A won deal is promoted here from the Sales Pipeline (once its contract is marked signed) and becomes a live project — code P-. Expand a project to track its delivery milestones, budgeted vs actual cost, and testimonial. Payment lines & margin variance come in the finance pass.

CRM

The task queue. Every task can be linked to a lead, sale or project by its code; because those records share one ID as a deal moves along, a task follows the deal from lead to sale to project. Tick a task to complete it, click a row to open it, or add tasks from any record's detail.

Pricing Model

Assumptions drive every tier. Change the day rate, markup, margin or overheads and all tiers recalculate. This is the only place the day rate lives.

Revenue Forecast

Two layers: Committed is real dated money from live projects' payment lines (100%). Weighted pipeline is sales deals at quote × their stage probability. Tap any figure to see exactly which records make it up.

Cash Flow Forecast

Money in from committed project payment lines (real due dates) plus weighted pipeline (sales × probability), less materials and fixed overhead, giving a running closing balance. Terms are set in Settings.

Transactions

The actual line — real money in and out, logged and reconciled. Link a transaction to a project or invoice code (e.g. P-103-INV1) so it ties back to the forecast. This is the source of month-end actuals; full forecast-vs-actual variance builds on top of it next.

Settings

Central configuration — the knobs that drive the rest of the system. Change them here and everything downstream re-calculates.
Branding
Pipeline stages

The stages each pipeline moves through. Rename, reorder, add or delete them — records keep their place because they follow a stage's hidden id, not its name. Each Sales stage carries a weighted percentage that weights the forecast, cash flow and dashboard; you can still override a single deal in its Sales Pipeline detail. Deleting a stage that holds records asks where to move them.

Data & backup

Your changes save automatically to this browser on this device. They stay put when you close and reopen — but they don't yet sync across devices (that's the next upgrade). Export a backup regularly so nothing can be lost; Import restores a backup or moves your data to another device.

Cloud database — multi-device sync

Connect to your Supabase database so the tracker syncs across devices and is backed up server-side, instead of living only in this browser. First-time setup: run the SQL below once in Supabase, then paste your Project URL and publishable key and hit Connect. (Logins come in the next step — for now, keep the link private.)

Show one-time setup SQL

In Supabase: left sidebar → SQL Editor → New query → paste this → Run. You only do this once.

create table if not exists tracker_data (
  id int primary key default 1,
  doc jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now(),
  constraint single_row check (id = 1)
);
insert into tracker_data (id, doc) values (1, '{}'::jsonb)
  on conflict (id) do nothing;
alter table tracker_data enable row level security;
create policy "app read"   on tracker_data for select using (true);
create policy "app insert" on tracker_data for insert with check (true);
create policy "app update" on tracker_data for update using (true) with check (true);
User accounts

Add team members, reset passwords, or remove access. Each person logs in with their own username and password. (Only admins see this panel.)

Approvals

Quotes waiting for a decision. Approvals are a team process, not security: anyone with the login can choose any name. Turn lanes on in Settings > Approvals.

Quotes

Build a quote from supplier prices, labour and delivery. Click a quote to open the builder.

Suppliers

The merchants and trades we buy from — contacts, terms and notes in one place. Click a supplier to open it. Suppliers are made inactive rather than deleted, so their history stays.

Setup & Admin Checklist

The temporary setup list — registration, insurance, and purchases needed to start taking on paid work. Retires once complete.

Actions

The action log from the weekly catch-up. Click any cell to edit. Drag the edge of a column header to resize it. Owner fields suggest from the team but accept anyone. Overdue items (deadline passed, not Done) highlight automatically.
